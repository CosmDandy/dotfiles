# Pi в Linux- и macOS-конфигурации

Pi отслеживает `stable` отдельным source-input в `platform/nix/flake.nix`;
точная ревизия закреплена в `flake.lock`. `upd` обновляет её до текущего стабильного
релиза, а `upd install` использует существующий lock. Используется официальный
`nix/package.nix`, а не глобальный npm install или обновляемый install.sh.

## Где подключается

- `home/default.nix` импортирует `home/pi.nix`: оба Linux-профиля, `core` и `devops`.
- Этот же Home Manager-модуль используется в NixOS-конфигурации.
- macOS импортирует тот же `home/pi.nix` через `home/darwin.nix`; `pi` и
  `pi-statusline` устанавливаются через `environment.systemPackages`.
- Ссылки используют `~/dotfiles` на Linux и `~/.dotfiles` на macOS.
- Установка, настройки и приватный сабмодуль Claude Code не изменяются.
- `pi` и `pi-statusline` входят в Linux-профиль; на обеих платформах `.local/bin/pi` указывает на Nix,
  чтобы старый shim установщика не перекрывал закреплённый пакет.

`upd` — штатная точка обновления Linux, NixOS и macOS; система определяется
автоматически. `upd install` применяет локальный конфиг без обновления зависимостей.
На NixOS используется системный rebuild, не отдельный home-manager switch.
Перед активацией macOS проверить сборку `darwin-rebuild build`.
Сборка macOS требует Mac или соответствующего Nix builder.
`pi update` не обновляет Nix-пакет: версия меняется через flake и lock.

## Файлы и состояние

Расширения, темы и keybindings — живые ссылки на `tools/pi/`.
Изменения подхватываются через `/reload`. Go-рендерер собирает Nix;
ссылка `.pi/agent/bin/solarized-statusline` сохраняет контракт расширения.
`~/.pi/agent/AGENTS.md` — такая же живая ссылка на `tools/pi/AGENTS.md`,
как `~/.claude/CLAUDE.md` на свой файл. Правки текста и существующих навыков
не требуют сборки: достаточно `/reload` или новой сессии.

`settings.json` копируется, если файла ещё нет. В существующий файл Home Manager
добавляет недостающие настройки `subagents`, не меняя остальные ключи и явно
заданные значения. OAuth, API-ключи, MCP-авторизации,
история, кеши, каталог моделей и device ID не входят в dotfiles и не перемещаются
в Nix store. Локальные MCP-конфигурации также не копируются.

При первой активации уже существующие файлы Pi и старый `.local/bin/pi` могут
потребовать штатного механизма backup Home Manager. Не удалять `~/.pi/agent`
целиком: там авторизации и история. Перед switch выполнить build и dry-run;
проверить, что затронуты только ожидаемые ссылки. Текущая сессия продолжает
использовать уже загруженное расширение до `/reload`.

## Переключение моделей

Новые сессии стартуют с GPT‑6.2 Sol Xhigh. `Ctrl+P` переключает Sol Xhigh → Sol Medium → Astra Xhigh. `sol-medium` — локальный пункт списка: запросы уходят в тот же GPT‑6.2 Sol строго с уровнем `medium`. Он нужен, потому что Pi не добавляет один ID в цикл дважды.

## Названия сессий

`session-auto-title` называет новые сохраняемые сессии в TUI после первого
успешного ответа. Текущая модель получает отдельным запросом только начало первого
текстового сообщения (до 2000 символов), без истории и инструментов. Название
на английском: желательно до шести слов, максимум восемь. Оно видно в `/resume`;
`/name` всегда имеет приоритет. Ошибка запроса не мешает чату.

## Vim-навигация по сессии

В fullscreen `Esc` из поля ввода выбирает последний видимый блок — вызов
инструмента или ответ модели — независимо от клавиши прерывания (`Ctrl+C`
в наших профилях). Красные
относительные номера рисуются цветным слоем поверх левого края ленты,
без отдельной полосы. Двузначные метки тоже остаются слева, в том числе
в таблицах и на переносах. У текущей строки бирюзовый фон; `▸` отмечает блок. Текст не сдвигается при `Esc`,
а прыжок прокручивает ленту лишь до ближайшего края, если цель за экраном.
В режиме навигации видны заголовки вызовов; вывод показывается только внутри
выбранного вызова. Возврат к вводу восстанавливает обычный вид ленты.
Сразу после `Esc` над полем ввода горит `NORMAL`: метка занимает свободное
место рядом со статусом и не закрывает его. Лента становится чёрно-белой
без сильного затемнения, а номера, курсор и выделение остаются цветными.
В открытом блоке восстанавливаются цвета темы: фон, подсветка синтаксиса
и diff. Нижний блок от виджетов до футера приглушается сильнее. `v` меняет метку на `VISUAL`, а возврат к вводу
восстанавливает цвета.
Во время генерации работает штатная клавиша прерывания. В regular-режиме,
где прокруткой управляет терминал, поведение `Esc` не меняется.

| Клавиши | Действие |
| --- | --- |
| `↑/↓`, `k/j`, например `3↑` | Перейти на один или несколько блоков |
| `Ctrl+U/D`, `Ctrl+B/F` | Прокрутить на полстраницы или на страницу; следующий прыжок начинается от видимой области |
| `→` или `Enter` | Открыть блок и перейти к его тексту (`↑/↓`, `k/j` — по экранным строкам, `h/l` — по символам) |
| `w/b/e`, `W/B/E` | Внутри блока: вперёд, назад и к концу слова; прописные буквы игнорируют пунктуацию внутри слова |
| `0`, `^`, `$` | Внутри блока: начало строки, первый непробельный символ, конец строки |
| `←`, `Esc` или повторный `Enter` | Выйти из блока; `Esc` сначала снимает выделение, если оно есть |
| `v`, `V`, `y` | Выделить символы (`v`) или строки (`V`), а снаружи — блоки. `y` копирует выделенное; `✓` подтверждает копирование |
| `i` / `q` | Вернуться к вводу |
| `Ctrl+C` дважды подряд (до 650 мс) | Штатно выйти из Pi; одиночное нажатие прерывает генерацию или возвращает из Vim к вводу |
| `Shift+Enter` или `Ctrl+J` | Вставить новую строку при вводе. Конфиг Ghostty передаёт `Shift+Enter` отдельной CSI-u последовательностью, а не `Alt+Enter` |

Стартовый экран показывает `v1.6.0/cosm`; `pi --version` оставляет исходную
версию для проверок совместимости.

Это [патч Pi](patches/vim-transcript.patch), не расширение. Общий пакет `.#pi`
собирается с патчем для macOS, NixOS и Linux/Home Manager; на каждом стенде
применяется штатным `upd install` из той же ревизии dotfiles. После замены пакета
нужно перезапустить процесс Pi (при необходимости `pi -c`); `/reload` не меняет
запущенный бинарник. Сессии остаются на месте. Для пробы без активации на Mac,
из каталога проекта: `nix run ~/.dotfiles/platform/nix#pi -- --continue`.
Если пробная панель `/vim-session` ставилась вручную, убрать её ссылку из
`~/.pi/agent/extensions/`, чтобы она не перехватывала `Esc`.

## Длинные запросы

После отправки Pi показывает первые 6 и последние 3 экранные строки длинного
запроса. Посередине — приглушённая полоска с числом скрытых строк; короткие запросы
не меняются. В fullscreen щелчок в любом месте длинного сообщения раскрывает или
сворачивает его. Ссылки и выделение мышью работают как прежде. `Alt+O` (`Option+O`
на Mac) переключает последний длинный запрос из поля ввода, в том числе в regular.
Сворачивание меняет только вид ленты: модель и история сессии получают исходный текст.

## Вывод инструментов

`compact-tools` показывает Bash с жирным `$` вместо подписи `bash`.
Свёрнутые заголовки Bash и Codemode серые; подсветка кода появляется при раскрытии.
Тайм-аут Bash стоит после команды. Длительность вызова появляется справа с 10 секунд
выполнения; у более быстрых вызовов её нет даже при раскрытии.
Свёрнутые заголовки сразу занимают не более 70% ширины, не считая таймера справа.
У простых Bash-цепочек видны первые две содержательные команды, исходный оператор
и число остальных. `cd`, присваивания и `set` перед командой заменяются короткими
метками; условный префикс помечается `guarded`. Длинные пути сокращаются слева,
heredoc виден как метка без тела. Если синтаксис не распознан, заголовок показывает
начало исходной команды. В раскрытом Bash команда переносится без повторов,
а время стоит справа на последней строке
команды или, если не помещается, на следующей. Для простых `rg` и `find` видны
путь и число строк результата; конвейеры не получают счётчик. Во время выполнения
по заголовку проходит градиент: быстрее для коротких команд и контрастнее для
Codemode в светлой теме. Bash показывает живой хвост, только если команда ещё
выполняется через 600 мс и уже есть вывод. До этого виден только заголовок.
В хвосте до пяти экранных строк (до десяти для SSH); при переполнении первая
строка сообщает, сколько строк скрыто. По завершении хвост исчезает, при ошибке
остаётся метка `Failed`. Ручное раскрытие доступно без задержки и сохраняется после
завершения; в нём виден сохранённый лог с ANSI-цветами.
Раскрытые блоки слегка выделяются фоном: темнее основного в светлой теме и светлее в тёмной.
У прямых Bash-вызовов Docker, Ansible, Terraform, Kubernetes, Talos и ряда
команд диагностики Linux метка `DEVOPS` и аргументы видны сразу. Длинная команда
переносится по аргументам, частые флаги показываются вместе со значениями.
Для живого вывода `DEVOPS` действует то же правило. Сложные shell-сценарии
и вложенные команды Codemode не получают метку.
Вывод команды отделён
пустой строкой. `read` добавляет к пути приглушённый диапазон строк, например `src/app.ts:2-31`.
У `read`, `edit` и `write` длинный путь в свёрнутом заголовке обрезается слева,
чтобы сохранить имя файла; при раскрытии виден весь путь. `grep`, `find` и
`ls` — запрос или путь и число результатов; `write` — создан или перезаписан файл,
если это известно. MCP-вызовы показывают действие, сервер и короткий результат.
У Knowledge и Exa в заголовке также видны запрос, заметка или URL. При раскрытии
поиск показывает названия и выдержки, а чтение заметки или страницы — Markdown.
Нераспознанные ответы поиска остаются текстом, без предположений о числе результатов.
В полноэкранном режиме при раскрытии одного вызова по клику или через Vim
лента показывает начало блока, а не его хвост. `Ctrl+O` по-прежнему переключает
все блоки. Для завершённых вызовов оба вида хранятся отдельно в
кэше до 24 МиБ (оценка объёма строк) и до 4096 записей. Первое раскрытие,
смена ширины или темы могут потребовать повторной отрисовки.

Содержимое инструмента начинается на одну колонку правее его заголовка.
`edit` показывает diff через `delta`: приглушённые номера контекста, пробел после
`+`/`-`, оливковые добавления и терракотовые удаления. Зелёные и красные номера
изменений лежат на том же фоне, что и строка. Номера удалений берутся из старого
файла, остальные — из нового. Изменённый фрагмент заметнее.
Предпросмотр показывает до 12 строк с двумя строками контекста с каждой стороны
правки. Раскрытие показывает весь сохранённый патч в том же стиле. Если `delta`
недоступен или в истории нет патча, используется компактный diff Pi.
`write` не показывает diff и не нумерует строки.
Подсветка команд и прочитанного кода использует Pi, а не внешний процесс.

В `read`, `edit` и `write` проектные пути выделены оранжевым, системные
временные помечены приглушённым `[tmp]`, остальные — жёлтым `[external]`.
Проект — ближайший Git-репозиторий или рабочая папка, если Git-репозитория нет.
Diff временного файла свёрнут по умолчанию, ошибки всегда видны.

## Knowledge MCP

Рабочая программа модернизации: [MODERNIZATION.md](MODERNIZATION.md).
Первый согласованный шаг — подключение существующего Knowledge MCP.

На моделях `openai-codex` Pi сначала использует встроенный веб-поиск Codex,
когда нужно посмотреть что-то в интернете. Exa остаётся запасным поиском
и доступна другим провайдерам через `tool_search`. Первый запрос Pi не ждёт
подключения Exa. Отдельный ключ или Codex CLI не нужны.
В списке инструментов Codemode есть `tools.codex_web_search({ query })`:
он возвращает `answer` и `sources` со ссылками провайдера. Для поиска нужен
отдельный скрипт без `timeout_ms`: у запроса Codex свой лимит в 180 секунд.
Явный лимит скрипта короче 300 секунд отклоняется до запуска поиска, чтобы
Codemode не отменял его раньше времени. Другие скрипты сохраняют свои лимиты.
В запрос Codex передаётся только поисковая фраза, а не история сессии.

Home Manager на macOS и Linux добавляет `knowledge`, `exa` и `context7` из шаблона
`tools/pi/mcp.json` в `~/.pi/agent/mcp.json`. Если сервер с таким именем уже
настроен, запись остаётся как есть, включая URL, авторизацию и `enabled: false`.
Остальные серверы и настройки тоже сохраняются. Для другой сети можно изменить
URL в пользовательской конфигурации.

Bearer token читается при подключении из `~/.config/knowledge-platform/token`
или файла `KNOWLEDGE_TOKEN_FILE`. Значение не хранится в конфигурации, dotfiles
или Nix store и не передаётся аргументом процесса. Отсутствующий или пустой файл
вызывает ошибку подключения; не подставляется пустой bearer token.
Существующий механизм `dp secrets <id> knowledge` доставляет секрет в devcontainer.
Файл токена должен оставаться доступным только владельцу (`0600`).
После замены токена переподключить сервер через `/mcp` или выполнить `/reload`.

Используется `deferred` exposure: штатный `tool_search` обнаруживает инструменты
по необходимости, без постоянной загрузки всех схем и без включения Codemode.
Доступны поиск, чтение, связанные заметки, статус и предложения изменений;
это не read-only профиль прав. Изменения знаний по-прежнему только предлагаются,
а не записываются агентом напрямую в vault. Сторонний MCP-adapter не нужен.

Context7 ищет документацию публичных библиотек через удалённый MCP без локального npm-пакета.
Инструменты поиска библиотеки и чтения документации доступны также в Explore.

Проверка соединения — `pi mcp list --json`; в уже открытой сессии нужен `/reload`.
`node tools/pi/tests/mcp.test.mjs` с `PI_TEST_MODULES` по аналогии с тестами ниже
проверяет native loader и чтение отдельного токена, включая пустой/отсутствующий
файл и смену значения. Флаг `--live` дополнительно проверяет пользовательскую
конфигурацию, обнаружение инструментов и настоящий read-only поиск без LLM-вызовов
и без записи в vault. Содержимое заметок и секреты тест не печатает.

## Настройки запуска и клавиши

По умолчанию выбран `openai-codex` / `gpt-6.2-sol` с reasoning `xhigh`.
Codemode включён в дополнение к штатным инструментам через `defaultTools`.
Свёрнутый Codemode показывает счётчики вложенных инструментов, не JavaScript.
После 600 мс работы появляются до восьми вложенных вызовов с целью и статусом.
Длительность показывается с 10 секунд, в том числе у вложенных вызовов.
Ошибки и отмены видны сразу и остаются после завершения, даже если скрипт их обработал.
По раскрытию видны все вызовы в порядке запуска, затем скрипт и его вывод.
Сводка вложенного Bash использует полную команду из события старта или журнала
Pi при повторном открытии. Если Pi сохранил только обрезанный аргумент, показывается
исходный фрагмент без синтаксических догадок.
В основном редакторе одиночный `Ctrl+C` прерывает агента вместо Esc и не
очищает черновик. Двойной `Ctrl+C` или `Ctrl+D` при пустом вводе завершает Pi.
Двойное нажатие Esc ничего не открывает; в меню Esc по-прежнему закрывает выбор.
Настройки находятся в `settings.json`, привязки — в `keybindings.json`.
`Shift+Tab` между ходами переключает голубой `Explore` ↔ коралловый `Execute`.
Цвет режима виден в метке и рамке над полем ввода; заливки нет.
В `Explore` доступны чтение и поиск, но не Bash, Codemode или правки.
`Execute` возвращает прежние инструменты, не запуская новый ход.
`Option+R` переключает `Pair` ↔ `Autonomous`. В строке виден только выбранный `AUTONOMOUS`; профиль `Pair` используется по умолчанию без подписи;
`/execute` открывает меню для прямого выбора.
`Option+G` независимо включает делегирование для обоих профилей Execute.
В Explore запуск запрещён; `/reload` сбрасывает переключатель. `/agents`
открывает список запусков и не включает делегирование. Подробнее — ниже.
Режимы не ограничивают ручные команды пользователя.
`Option+T` меняет уровень reasoning, `Ctrl+T` показывает или скрывает его блоки.
`Option+P` (или `Ctrl+L`) открывает выбор модели, `Option+S` — выбор сессии.
`Option+A` не назначаем в Pi: в этой раскладке она переключает вкладки Ghostty.
Для `gpt-6.2-sol` автокомпактация начинается примерно при 60% окна Pi:
`reserveTokens: 200000` при окне 500 тыс. Последние 20 тыс. токенов Pi сохраняет
без пересказа по умолчанию. Уведомления о кэше и компактации включены для диагностики.
`/tree` по умолчанию показывает пользовательские реплики; при выходе из fullscreen
остаётся команда для возобновления. Mermaid отрисовывается после завершения ответа.
`/recap [фокус]` начинает отчёт с того, что осталось. Затем идут сделанное, решения
и проверки. Пустые секции пропускаются, заголовки не повторяются; галочка только
у сделанного. После автокомпактации отчёт опирается на саммари и свежие сообщения.
Команда не меняет файлы и не запускает компактацию.
`/c [область]` создаёт один локальный Conventional Commit без push.
`/c-ph [область]` создаёт такой же коммит и отправляет текущую ветку.
`/c-ph-pr [область]` после push открывает pull request на GitHub или возвращает
ссылку на уже открытый PR с теми же ветками.
Все три команды уточняют область, если она неясна или в индексе есть посторонние правки.
Команды с push спрашивают, прежде чем отправить другие неопубликованные коммиты.

## Агенты

[`pi-subagents`](https://github.com/nicobailon/pi-subagents/tree/v0.90.0)
поставляется через Nix как `.#pi-subagents`. Home Manager подключает
собранный пакет через `~/.pi/agent/subagent-package`, а `work-mode.ts` загружает
его. Локальные расширения остаются живыми ссылками на репозиторий; пакет и его
npm-зависимости закреплены lock-файлом и хешем сборки. Не устанавливать вторую
копию через `pi install`: обе зарегистрируют инструмент `subagent`.

- `Option+G` разрешает запуск в Execute. `/agents` показывает текущие и завершённые
  запуски, ход работы, результаты и управление ими.
- `/subagents` показывает типы агентов и даёт менять модель, reasoning и промпт.
  Глобальные роли лежат в `tools/pi/agents/`: Home Manager подключает весь каталог
  как `~/.pi/agent/agents` на macOS, NixOS, Linux и в dev-контейнерах.
  У всех шести общих ролей закреплена Astra X‑High. Для роли только одного
  проекта используй `.pi/agents/` в доверенном проекте.
- Если `~/.pi/agent/agents` уже обычный каталог, сверить его с `tools/pi/agents/`,
  сохранить свои роли и убрать старый каталог в резервную копию перед активацией.
  После активации изменение глобальной роли правит файл в dotfiles; для
  подхвата в открытой сессии нужен `/reload`.
- `/run scout <задача>` — чистая история. Добавить `--fork`, чтобы унаследовать
  ветку разговора, и `--bg`, чтобы продолжать работу в родителе.
- Модель по умолчанию — Sol Medium. Разрешены Sol, Sol Medium и Astra. Чтобы выбрать
  конкретный профиль на один запуск: `/run reviewer[model=openai-codex/gpt-6.2-astra:xhigh] <задача>`.
  Список ограничивает ID моделей; у обычных моделей reasoning можно переопределить.
- Модель использует `subagent` для одиночного запуска, `tasks` для параллельного или
  `chain` для последовательного; `bg_wait` ждёт фоновые результаты без ручного опроса.
  Стартовые роли — `scout`, `reviewer`, `oracle`; инструменты детей —
  `read`, `grep`, `find`, `ls` и, если запрошен ролью, `contact_supervisor`.
  Пишущие роли не включены.

Проверка без запросов к модели из корня репозитория:

```sh
PI_TEST_SUBAGENTS="$(nix build ./platform/nix#pi-subagents --no-link --print-out-paths)/lib/node_modules" \
  node tools/pi/tests/subagents.test.mjs
```

## Статуслайн

Редактор обведён тонкой серой рамкой с отступом в одну колонку от краёв.
Справа над рамкой видны Ready и фазы работы. Статистика сохраняется для каждого завершённого хода,
включая время коротких вызовов. Только при длительности хода от 30 секунд в ленте видна
приглушённая строка с общим временем, долями `wait`, `gen`, `tools` и `other`,
а также приблизительными `tok/s` там, где их можно измерить. При раскрытии видны
секунды по фазам и разбивка на Bash, другие инструменты и их пересечение. Вложенные вызовы
Codemode входят во время родительского инструмента. Строка не попадает в контекст модели.
Под редактором строка в стиле Claude Code: модель → reasoning без иконки,
строчными буквами → цветной процент контекста; справа — другие сессии Pi и лимиты.
Отступы нижней строки совпадают с отступами строки над рамкой.
Цвета reasoning: low — cyan, medium — серый как у модели, high — yellow,
xhigh — orange, max — red; off/minimal — нейтральные. В тёмной теме нижняя
строка использует ANSI faint; в светлой используется контрастный серый без faint.
Цвет рамки зависит от режима, а не от reasoning: сине-серый для `Explore`, оливково-серый для `Execute`. В покое справа неподвижное `· Ready` (приглушённый зелёный), после прерывания — `■ Interrupted` (жёлтый).
Во время работы справа только три движения: пульсирующая звезда при размышлении, волна при ожидании, выводе текста или подготовке вызова, вращающаяся точка при выполнении инструмента. Справа от звезды появляется заголовок текущей части резюме OpenAI, если он есть. Тело резюме и названия активных фаз не выводятся. Активные инструменты показаны слева серым сразу после режима, например `EXECUTE bash, read`. Имена — без аргументов и повторов; каждое исчезает после завершения последнего одноимённого вызова. При нехватке места сокращается подпись, не фаза. У `Ready` и `Interrupted` подписи нет.
В завершённых ответах отдельная строка маркера и её подпись выделяются жирным,
без рамки: `✔` зелёный, `✘` красный, `!` оранжевый, `?` жёлтый, `»` синий.
Цвета маркеров в обеих темах Solarized совпадают с Claude Code. Это оформление
ленты, а не изменение Markdown в истории: текст под заголовком, цитаты и код
остаются обычными. В тёмной теме пользовательские сообщения светлее раскрытых
вызовов; текст сообщений тоже осветлён, чтобы сохранить читаемость.

`Ctrl+T` скрывает блок рассуждений целиком, без заглушки; видимый текст рассуждений
серый. Ошибка команды помечается в самой ленте, а не в статуслайне.
Оба лимита показываются всегда, независимо от ширины терминала. При нехватке
места footer переносится на дополнительные строки, а не обрезается.
Неизвестные, отключённые и истёкшие окна скрыты; если окон нет, блока лимитов нет.
Полоска контекста и стоимость не показываются. Исчерпанное пятичасовое окно
обозначается иконкой обновления и временем сброса, без «you lose».
Контекст и расход `5h` выделяются сильнее при росте процента; у времени и прогноза
`5h` остаётся отдельный цвет тренда. Недельный лимит серый, пока расход укладывается
в ровный график, жёлтый при перерасходе до 16 часов бюджета включительно (≈9,5 п.п.)
и красный выше.
Отсчёт в часах появляется, когда до прогнозируемого исчерпания не больше времени,
чем потом останется до сброса. Для прогноза используется средний расход с начала
окна, не раньше чем через 12 часов после его открытия.

`◉ N` — общее число реально работающих локальных сессий Pi, включая текущую.
Счётчик появляется только при `N >= 2`; простаивающие окна и ожидающие ввода
сессии не учитываются. Состояние публикуется в
`~/.pi/agent/cache/statusline/sessions/<pid>.json` при смене состояния и каждые
15 секунд; закрытые процессы и записи старше 90 секунд не учитываются.
Для учёта уже открытых сессий выполнить `/reload` в каждой из них.
История Pi и сессии Claude Code не читаются.

`/statusline` переключает полностью штатный редактор и footer Pi;
повторный вызов возвращает расширение. `/statusline-metrics` показывает замеры
ответа, `/statusline-limits` — наблюдаемые заголовки и общий кеш лимитов.

Проценты лимитов означают **израсходовано**, не остаток: `44%` соответствует
`56%` оставшегося бюджета. Квота относится к подписке, не к проекту.
Локальные окна одного провайдера используют общий кеш
`~/.pi/agent/cache/statusline/<provider>/limits-<pid>.json`: каждое окно выбирается
по самому свежему наблюдению API, независимо от проекта, модели и сессии.
Когда Codex явно отключает пятичасовое окно, кеш запоминает это и скрывает
старые значения до нового наблюдения окна. Ответ без заголовков лимитов кеш не сбрасывает.
Атомарные снимки отдельных процессов не перезаписывают друг друга и переживают
reload/закрытие окна. Для уже запущенной старой версии читается и существующая
безопасная transport-диагностика. Авторизации и токены не читаются.

Без нового ответа API нет нового измерения; обновление кеша в других локальных
окнах подхватывается каждые 15 секунд. Расход во внешних клиентах виден только
после следующего наблюдения API. Кеши разных машин не синхронизируются.
Сдвиг времени сброса на несколько секунд не считается новым окном; история
для прогноза никогда не заменяет актуальный процент из ответа провайдера.

## Инструкции и типы промптов

`~/.pi/agent/AGENTS.md` — глобальный аналог Claude Code `CLAUDE.md`.
Pi также понимает имя `CLAUDE.md` напрямую. В одном каталоге выбирается первый
существующий файл: `AGENTS.override.md`, `AGENTS.md`, `AGENTS.MD`, `CLAUDE.md`,
`CLAUDE.MD`. Глобальный файл и инструкции каталогов от корня до рабочего каталога
добавляются в контекст вместе; инструкции вложенных каталогов вне этого пути
автоматически не подгружаются.

Источник инструкций Pi — `tools/pi/AGENTS.md`, независимо от Claude. Home Manager
создаёт ссылку при активации. При переходе со старой обычной копии сначала сверить
её с репозиторием и сохранить локальные правки. Сборка без активации ссылки в
домашнем каталоге не меняет. Новый путь в `home.file` требует активации; изменение
содержимого уже подключённого файла — нет.

Системный промпт собирается кодом Pi (`dist/core/system-prompt.js`), а не хранится
целиком в одном пользовательском Markdown-файле. Его части:

- Штатная основа Pi: роль агента, инструкции инструментов и ссылки на документацию.
- `SYSTEM.md` в agent directory или `.pi/SYSTEM.md` — замена штатной основы,
  не пользовательских контекстных файлов и списка навыков.
- `APPEND_SYSTEM.md` в тех же местах — дополнение к системному промпту.
  При наличии доверенного проектного файла глобальный одноимённый файл не добавляется.
- `AGENTS.md` / `CLAUDE.md` — постоянно загружаемые пользовательские инструкции.
- `skills/*/SKILL.md` — специализированные инструкции: обычно в промпт попадают
  только имя, описание и путь; полное тело читается при необходимости.
- `prompts/*.md` — шаблоны slash-команд, разворачиваемые в пользовательское сообщение.
- Расширения могут изменять промпт и контекст программно, но наши UI-расширения
  этого не делают. CLI также поддерживает `--system-prompt` и `--append-system-prompt`.

Пользовательских `SYSTEM.md` и `APPEND_SYSTEM.md` нет.
Home Manager подключает четыре навыка из `tools/pi/skills/`: `ops-net`,
`ops-remote`, `ops-metal`, `ops-vm`. Это отдельные копии для Pi, а не ссылки
на исходники Claude. Другие Claude skills и scoped rules не подключаются.
Активация удаляет только известные старые симлинки остальных навыков;
оригиналы Claude и самостоятельные пользовательские файлы сохраняются.

### Что осталось воспроизвести в Pi после Claude Code

- **Фоновые команды.** Убраны `run_in_background` и обещание автоматического ухода Bash
  в фон через 30 секунд. Нужно уметь запустить долгую команду, получить её вывод и код
  завершения и заметить зависание, не перекладывая наблюдение на пользователя.
- **Ожидание событий.** Убран `Monitor`. Нужны одноразовое ожидание и наблюдение за
  потоком с уведомлением как об успехе, так и об ошибке, без ручного опроса.
- **Линт после правки.** Убрана ссылка на `PostToolUse`: автоматический запуск линтера
  средствами Pi ещё не подключён. Пока агент сам запускает проверку изменённого кода.

Не переносим предположения, что shell всегда zsh и что рабочие деревья находятся
в `.claude/worktrees/`. Ссылка на `/goal` оставлена до отдельного решения.

## Проверки

Из `platform/nix`:

```sh
nix flake check --no-build --all-systems --no-warn-dirty
nix build .#pi-statusline --no-link
nix build .#pi --no-link
```

Go-тесты из `tools/pi/statusline`: `go test ./...`, `go vet ./...`.
UI-тест использует реальный загрузчик и редактор Pi, не делает запросов к модели:

```sh
PI_TEST_MODULES="$(nix build ./platform/nix#pi --no-link --print-out-paths)/lib/pi/node_modules" \
  node tools/pi/tests/frame.test.mjs
```

Для UI-теста требуется установленный через Home Manager `pi-statusline`, доступный
расширению по `.pi/agent/bin/solarized-statusline`. На машине со старым managed
installer путь к его node_modules определяется автоматически. Для проверки свежей сборки
можно передать путь к бинарнику в `PI_TEST_STATUSLINE`. Штатное подключение рендерера:
тест запускает именно установленный бинарник. Проверяются обычные границы,
отсутствие карточки и стоимости, порядок метрик, цвета, скорость, состояния,
очередь, ошибки, переносы, узкие размеры, переключение штатного интерфейса
и счётчики сессий с живыми, завершёнными и устаревшими процессами.
Тест также печатает штатный и новый интерфейс на демонстрационных данных.
`node tools/pi/tests/instructions.test.mjs` с тем же `PI_TEST_MODULES` проверяет
нативную загрузку AGENTS.md через ссылку, видимость изменений в исходнике и приоритет
проектных инструкций. С `--live` проверяются путь к исходнику и загрузка четырёх ops-навыков.
