# Pi в Linux-конфигурации

Pi закреплён на `v1.4.0` отдельным source-input в `platform/nix/flake.nix` и точной
ревизией в `flake.lock`. Используется официальный `nix/package.nix` этого релиза,
а не глобальный npm install или обновляемый install.sh.

## Где подключается

- `home/default.nix` импортирует `home/pi.nix`: оба Linux-профиля, `core` и `devops`.
- Этот же Home Manager-модуль используется в NixOS-конфигурации.
- macOS импортирует `home/darwin.nix`, поэтому Pi там не устанавливается.
- Установка, настройки и приватный сабмодуль Claude Code не изменяются.
- `pi` и `pi-statusline` входят в Linux-профиль; `.local/bin/pi` указывает на Nix,
  чтобы старый shim установщика не перекрывал закреплённый пакет.

`updl` остаётся штатной точкой обновления Linux. На NixOS применяется системная
конфигурация через её штатный rebuild, не отдельный home-manager switch.
`pi update` не обновляет Nix-пакет: версия меняется через flake и lock.

## Файлы и состояние

Расширение, темы и APPEND_SYSTEM.md — живые ссылки на `tools/pi/`, по принятой в
репозитории схеме. Изменения подхватываются через `/reload`. Go-рендерер собирает
Nix; ссылка `.pi/agent/bin/solarized-statusline` сохраняет контракт расширения.

`settings.json` копируется только при первом запуске активации, если файла ещё
нет. Существующие настройки не перезаписываются. OAuth, API-ключи, MCP-авторизации,
история, кеши, каталог моделей и device ID не входят в dotfiles и не перемещаются
в Nix store. Локальные MCP-конфигурации также не копируются.

При первой активации уже существующие файлы Pi и старый `.local/bin/pi` могут
потребовать штатного механизма backup Home Manager. Не удалять `~/.pi/agent`
целиком: там авторизации и история. Перед switch выполнить build и dry-run;
проверить, что затронуты только ожидаемые ссылки. Текущая сессия продолжает
использовать уже загруженное расширение до `/reload`.

## Навыки и приватность

`home/pi.nix` содержит явный allowlist из десяти навыков: commit, compliance,
ops-metal, ops-net, ops-remote, ops-vm, performance, skill-tester, spec, ux.
Они подключаются ссылками из существующего приватного `tools/claude/custom`,
**не копируются в публичный репозиторий**. Отсутствующий сабмодуль означает, что
эти навыки недоступны; публичное расширение и темы от него не зависят.

Учёт времени, личные журналы, Claude history и базы знаний не подключаются:
`c-brag`, `c-call`, `c-daylog`, `c-log`, `knowledge`, `lab`. Активация удаляет только
их известные старые ссылки из Pi; оригиналы Claude и самостоятельные файлы
пользователя не трогает. Правила также читаются из приватного сабмодуля, а
APPEND_SYSTEM.md объясняет их область и отличия Pi от Claude Code.

Это повторное использование инструкций, не перенос Claude hooks, permissions,
subagents или macOS/MCP-зависимостей. Навыки с такими зависимостями обязаны
проверять их доступность. Публикация отдельных навыков требует отдельной
ревизии их текста и вспомогательных файлов.

## Изучение репозитория

APPEND_SYSTEM.md требует сначала проследить entry points, imports, платформы,
существующие инструменты и проверки; только затем предлагать интеграцию.
Investigation → implementation → verification — рабочий порядок, а не выдуманные
режимы Pi. Отсутствующий независимый reviewer обозначается как ограничение.

GitHub и GitLab доступны через уже включённые `gh` и `glab`. Веб-поиск и новые MCP
этот модуль не устанавливает: нужен отдельно выбранный сервис и авторизация.

## Проверки

Из `platform/nix`:

```sh
nix flake check --no-build --all-systems --no-warn-dirty
nix build .#pi-statusline --no-link
nix build .#pi --no-link
```

Go-тесты из `tools/pi/statusline`: `go test ./...`, `go vet ./...`.
UI-тест использует реальный загрузчик и редактор Pi, не делает запросов к модели:

```sh
PI_TEST_MODULES="$(nix build ./platform/nix#pi --no-link --print-out-paths)/lib/pi/node_modules" \
  node tools/pi/tests/frame.test.mjs
```

Для UI-теста требуется установленный через Home Manager `pi-statusline`, доступный
расширению по `.pi/agent/bin/solarized-statusline`. На машине со старым managed
installer путь к его node_modules определяется автоматически. Проверяются цвета,
полустрочные края, отступы, hints, метрики, состояния, очередь, ошибки, переносы,
узкие размеры и восстановление стандартного редактора.
