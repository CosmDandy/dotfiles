# IPMI и serial-консоль: сервер без монитора

Методичка по управлению сервером с мака без клавиатуры и монитора —
питание, BIOS, консоль загрузки. Всё проверено на IBM System x3550 M3
(IMM v1, firmware 1.55) из домашней сети, `ipmitool` стоит через
`darwin-configuration.nix`.

## Три уровня доступа к серверу

| Уровень | Когда работает | Что нужно |
|---|---|---|
| SSH | только когда ОС загружена и сеть настроена | ничего |
| **SOL (serial-консоль)** | от BIOS до логина, сеть ОС не нужна | BMC + один раз включить редирект в UEFI |
| KVM-over-IP | всегда, вкл. выключенный сервер | лицензия BMC (см. ниже) |

BMC (Baseboard Management Controller) — отдельный мини-компьютер на
материнке, живёт от дежурного питания: работает, как только БП в розетке,
ещё до включения сервера. Названия по вендорам: IMM (IBM), iLO (HP),
iDRAC (Dell), просто BMC (Supermicro). Протокол общий — IPMI.

## Serial порт: почему это работает везде

UART (COM-порт, RS-232) — примитивнейшее железо: TX, RX, земля; байты
летят по одному. Управляется парой регистров без драйверов и стека,
поэтому прошивка умеет писать в него с первых миллисекунд после подачи
питания. Видеокарте, USB, сети нужна инициализация — serial работает
сразу. Отсюда: BIOS, GRUB, ядро, логин — всё можно увести в serial.

Классические параметры: **115200 8N1** (baud 115200, 8 data, no parity,
1 stop). Старое/сетевое железо — часто 9600.

## SOL: serial поверх сети

SOL (Serial over LAN) — тот же serial, но «кабель» заменён сетью,
а вторым концом провода служит BMC:

```
UEFI / GRUB / ядро ──▶ UART (думают, что там кабель)
                        │ BMC перехватывает байты
                        ▼
                 IPMI-пакеты, UDP 623, шифровано
                        ▼
        мак: ipmitool sol activate ──▶ терминал
```

Сервер не знает, что кабеля нет: нажатия с мака BMC «впрыскивает»
в UART как будто с физического терминала.

## ipmitool

В `darwin-configuration.nix` → `environment.systemPackages` (нужен на
маке, в devpod-контейнерах — нет).

Структура: `ipmitool [опции] <группа> <подкоманда>`. `-I lanplus`
обязателен — это IPMI v2.0, без него нет SOL и нормального шифрования.

Пароль — не в командной строке (`-P` светится в истории и `ps`),
а через окружение и `-E`:

```bash
 export IPMI_PASSWORD='...'   # пробел в начале — мимо истории zsh
imm() { ipmitool -I lanplus -H 10.0.1.100 -U cosmdandy -E "$@"; }
```

### Шпаргалка команд

| Команда | Что делает |
|---|---|
| `chassis power status` / `on` / `off` / `cycle` | питание |
| `chassis status` | питание + faults (PSU, cooling, intrusion) |
| `chassis identify` | помигать лампочкой (найти сервер в стойке) |
| `sol activate` / `deactivate` | консоль / прибить повисшую сессию |
| `sol info` | настройки SOL (enabled, скорость, порт) |
| `sdr elist` | все сенсоры: температуры, вентиляторы, вольтажи |
| `sel` / `sel elist` | журнал железных событий (кратко / целиком) |
| `fru print` | инвентарь: модель, серийники, DIMM, БП |
| `lan print 1` | сетевые настройки BMC |
| `user list 1` | юзеры BMC |
| `user set password <id> '<pass>'` | сменить пароль юзера |
| `mc info` | версия firmware BMC |
| `mc reset cold` | перезагрузить завиcший BMC (сервер не трогает) |

SEL — журнал, а не текущее состояние: записи об отремонтированных
проблемах не «рассасываются». Смотреть свежий хвост: `sel elist | tail`.

### SOL-сессия: поведение

- Эскейпы (только после Enter): `~.` — выйти, `~?` — помощь, `~~` —
  послать сам символ `~`. Через ssh удваивать: `~~.` — иначе эскейп
  съест ssh и порвёт ssh-сессию.
- Сессия **одна** на BMC. Вторая не подключится, пока жива первая;
  повисшую убивает `sol deactivate`.
- «SOL session closed by BMC» при перезагрузке сервера — норма: BMC
  переинициализирует порт. Просто переподключиться.
- Кривая «лесенка» в выводе — норма: сырой tty шлёт LF без CR.
- Экран UEFI всегда **80×25** — у serial нет обратного канала про размер
  терминала (нет аналога EDID). Увеличить можно только шрифтом
  (`Cmd +` в ghostty; в tmux — `prefix z` на панель).
- В загруженном Linux размер чинится: `stty rows 50 cols 180` (или
  `resize`) — после этого tmux/vim/htop работают полноэкранно.

### Esc против тильды: два разных эскейпа

Тильдовые (`~.`, `~?`) — **локальные команды ipmitool**, до сервера не
доходят, распознаются только после Enter — потому работают чётко.

Клавиша **Esc** — байт ESC, улетающий серверу, и по serial он капризен:

- ESC — префикс всех спецклавиш (стрелка = `ESC [ A`), одинокий Esc
  парсер UEFI отличает от начала последовательности только по таймауту;
- SOL буферизует байты пачками (150 мс) — последовательности доезжают
  разорванными, стрелки/Esc иногда глючат. Нажал Esc — пауза, потом
  дальше;
- IBM UEFI по serial принимает Esc-подстановки вместо F-клавиш —
  надёжнее настоящих F:

| Клавиша | По serial |
|---|---|
| F1 (Setup) | `Esc` `1` |
| F2…F9 | `Esc` + цифра |
| F10 | `Esc` `0` |
| F12 (boot menu) | `Esc` `@` |

## Где это есть

BMC — стандарт серверного железа лет двадцать как; под капотом почти
везде чип ASPEED AST2500/2600 (отдельный ARM со своей сетью). Dell —
iDRAC, HPE — iLO, IBM/Lenovo — IMM → IMM2 → XCC, Supermicro — BMC
(HTML5 KVM бесплатно), Cisco — CIMC, ASRock Rack/Gigabyte — MegaRAC
или OpenBMC. IPMI/`ipmitool`/SOL работают на всех; современный
интерфейс — **Redfish** (REST/JSON поверх HTTPS, для Ansible/скриптов).

Где BMC нет (десктопы, ноуты, мини-ПК): PiKVM/JetKVM (внешний
KVM-over-IP в HDMI+USB) или Intel vPro/AMT — встроенный в чипсет
«бизнесовых» машин аналог.

**BMC никогда не выставлять в интернет** — протокол старый, UDP 623
сканируют постоянно. Удалённый доступ — только через VPN до локалки.

## x3550 M3 / IMM: конкретика

- Дефолты IBM IMM: юзер `USERID` / пароль `PASSW0RD` (ноль вместо O);
  без DHCP — статический `192.168.70.125/24`. MAC BMC — на выдвижной
  бирке спереди сервера (искать IP в аренде DHCP по нему).
- Дефолтного `USERID` (ID 2, ADMINISTRATOR) — отключить или сменить
  пароль, предварительно проверив, что свой админ работает.
- Графический KVM (Remote Control) на IMM v1 требует лицензию FoD
  «IMM Advanced Upgrade» и работает через старый Java-апплет — на
  современном маке боль. SOL лицензии не требует.
- SOL на IMM: enabled из коробки, 115.2 kbps, шифрование форсировано,
  UDP 623.

### UEFI: включение редиректа (один раз, нужен монитор)

`F1` → System Settings → Devices and I/O Ports → Console Redirection
Settings:

| Параметр | Значение |
|---|---|
| **SP Redirection** | **Enable** — главное: консоль → сервис-процессор (IMM) → SOL |
| **Active After Boot** | **Enable** — иначе редирект умрёт после POST |
| COM Port 1 / Console Redirection / Remote Console / Serial Port Sharing | Enable |
| Serial Port Access Mode | Shared |
| COM1: baud/data/parity/stop | 115200 / 8 / none / 1 (= `sol info`) |
| Terminal emulation | ANSI |
| Legacy Option ROM display | COM Port 1 (экраны RAID и пр. тоже в консоль) |

После сохранения POST, логотип и UEFI Setup рисуются в SOL-сессии,
клавиатура мака работает как физическая. POST у M3 с 192 GB — 3–5 минут,
тишина в начале загрузки — норма.

## Зачем это девопсу

В облачной рутине BMC не трогаешь годами — но слой никуда не делся,
и знание его компаундится:

- **Cloud serial console = тот же SOL.** EC2 Serial Console, GCP,
  Azure — когда VM зависла и SSH мёртв, подключаешься к её serial
  через API и видишь то же, что здесь по SOL. Кто гонял на железе —
  в облаке делает не задумываясь.
- **Bare-metal provisioning** (MAAS, Tinkerbell, Ironic, Talos на
  железе) под капотом делает ровно это: IPMI/Redfish power on → PXE →
  SOL для дебага. У Talos SSH нет — serial единственная консоль.
- **NUMA** — это не про старые серверы, а про k8s: Topology/CPU
  Manager, прибивка латентных подов к узлу — та же картинка
  «своя/чужая память».
- **Watchdog-паттерн** живёт на всех этажах: liveness probe в k8s,
  `WatchdogSec=` в systemd — контракт «таймер + гладильщик».
- Главное — исчезает «магический этаж», ниже которого «само работает».
  Абстракция течёт всегда; разница между мидлом и SRE — способность
  спокойно спуститься на этаж ниже в худший день, на инциденте.
